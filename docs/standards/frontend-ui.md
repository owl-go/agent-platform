# Agent Workspace · UI 设计规范

> 版本 v1.0 ｜ 纯视觉规范：色彩、字体、间距、布局、组件样式
> 适用：AI Agent 工作平台（Web 端）
> 使用方式：整体投喂给 AI，用于生成界面或还原设计稿

---

## 0. 设计定位

这是一个**工具型 + 高密度**的 Agent 工作平台，用户是技术向人群（研发 / 运维 / 平台工程），单次使用时长长、信息密度高。

**三条定调原则**

| 原则 | 说明 |
|---|---|
| 克制 | 界面本身要"消失"。装饰让位于内容，用户来这里是把事办完，不是逛的 |
| 密度 | 中高密度。一屏多看几行数据，留白收敛，不学 C 端大留白 |
| 一致 | 全站只有一套层级语言。一致性比丰富度重要 |

**一句话标准**：判断一套 UI 好不好的标准不是"好不好看"，而是**扫读效率、误操作率、学习成本**。

## 1. 色彩系统

### 1.1 中性灰阶

页面层级靠**灰底白卡**划分，这比加边框干净得多。

| Token | 色值 | 用途 |
|---|---|---|
| `n0` | `#FFFFFF` | 卡片、弹层、主内容背景 |
| `n1` | `#FBFBFC` | 卡片头部、表头底 |
| `n2` | `#F5F7FA` | 页面底、侧栏底、内嵌块 |
| `n3` | `#EEF0F4` | hover 态、内嵌分隔 |
| `n4` | `#E5E7EB` | 分割线、默认边框 |
| `n5` | `#D1D5DB` | 禁用态、空心标记描边 |
| `n6` | `#9CA3AF` | 辅助文字、元信息（**对比度下限**） |
| `n7` | `#6B7280` | 次要正文 |
| `n8` | `#4B5563` | 正文 |
| `n9` | `#374151` | 强调正文 |
| `n10` | `#1F2937` | 标题 |

### 1.2 功能色

| Token | 色值 | 语义 | 使用约束 |
|---|---|---|---|
| 主色 `primary` | `#2563EB` | 主按钮、选中态、链接 | **整屏占比 ≤ 5%**；一个区域内只允许一个实心主按钮 |
| Agent 紫 `agent` | `#7C3AED` | Agent 身份、AI 生成内容标记 | **关键手法**：所有 AI 相关元素统一用紫，与普通功能的蓝区分开，用户一眼能分辨"这块是 AI 干的" |
| 执行中 `running` | `#0891B2` | 运行中 | 仅用于进行中的步骤、节点、指示灯 |
| 成功 `success` | `#16A34A` | 已完成、成功、明确批准动作 | 仅用于状态与批准主操作，禁止装饰 |
| 需确认 `warning` | `#EA580C` | 需确认、不可逆操作 | 审批卡专用，全站视觉权重最高的卡片色 |
| 危险 `danger` | `#DC2626` | 失败、中断、毁灭性操作 | 危险按钮用**红色文字/描边**按钮，不做实心红块 |

配套浅底色与描边（用于卡片背景）：

| 语义 | 浅底 | 描边 |
|---|---|---|
| primary | `#EFF6FF` | `#BFDBFE` |
| agent | `#F5F3FF` | `#DDD6FE` |
| running | `#ECFEFF` | `#A5F3FC` |
| success | `#F0FDF4` | `#BBF7D0` |
| warning | `#FFF7ED` | `#FED7AA` |
| danger | `#FEF2F2` | `#FECACA` |

### 1.3 色彩使用规则

- 🚫 **禁止硬编码色值**——一律用 token
- 🚫 语义色不得混用：`warning` 只能表示"需确认/不可逆"，不得用于普通提示
- 🚫 不给图标"上色装饰"——图标默认用中性灰，只在表达状态时才上语义色
- ✅ **对比度红线**：正文对背景 ≥ 4.5:1，大字 ≥ 3:1。禁止 `#999` 配白底（实测仅 2.8:1）。辅助文字最浅到 `n6`
- ✅ 长时间盯屏场景，饱和度必须压住。高饱和色块铺满屏，半小时就累
- ✅ 主色占比自检方法：截图后眯眼看，蓝色面积不应超过一个巴掌

## 2. 字体

### 2.1 字体栈

```
无衬线（默认）
-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC",
"Hiragino Sans GB", "Microsoft YaHei", sans-serif

等宽（代码 / 参数 / 耗时 / token 数 / 时间戳）
"SF Mono", Menlo, Consolas, "Liberation Mono", monospace
```

优先系统字体栈，不引入自定义字体，理由是零加载成本且不挑环境。

### 2.2 字号阶梯

| 层级 | 字号 | 行高 | 字重 | 用途 |
|---|---|---|---|---|
| H1 | 24px | 1.4 | 700 | 页面主标题 |
| H2 | 20px | 1.4 | 700 | 区块标题 |
| H3 | 16px | 1.5 | 650 | 卡片标题、分区标题 |
| 正文 | **13.5px** | **1.75** | 400 | 对话流正文（比常规 B 端大 0.5px，长文更友好） |
| 卡片内容 | 13px | 1.6 | 400 | 卡片、面板内文字 |
| 列表项 | 12.5px | 1.6 | 400 | 会话项、文档项 |
| 元信息 | 11.5px | 1.5 | 400 | 耗时、token、时间戳（**配等宽字体**） |
| 分组标题 | 11px | 1.5 | 600 | 列表分组标签，字间距 0.04em |

### 2.3 排版规则

- ✅ 层级靠**字重 + 灰度**建立，不靠加大字号
- ✅ 所有数字、代码、耗时、token 量**必须等宽字体**——方便纵向比对
- ✅ 表格数字列右对齐 + 等宽，方便扫读
- 🚫 正文行宽不超过 760px（见第 4 节）
- 🚫 字重只保留 400 / 600 / 700 三档，禁止出现 500（渲染差异大）

## 3. 间距、圆角、阴影、动效

### 3.1 间距（4px 基准栅格）

```
4 / 8 / 12 / 16 / 20 / 24 / 32 px
```

| 场景 | 值 |
|---|---|
| 卡片内边距 | 16px |
| 列表项内边距 | 8px 12px |
| 卡片之间间距 | 12px |
| 区块之间间距 | 24px |
| 页面主区间距 | 32px |
| 图标与文字间距 | 8px |
| 标签/按钮内边距 | 4px 10px |

### 3.2 圆角

| 对象 | 值 |
|---|---|
| 小控件（按钮、标签、角标） | 6px |
| 输入框、工具卡 | 8px |
| 卡片 | 12px |
| 大容器、弹层 | 16px |

🚫 **圆角上限 16px**。超过会让 B 端产品立刻显得像 C 端，专业感立刻掉。

### 3.3 边框与阴影

| 对象 | 规格 |
|---|---|
| 默认分割线 | 1px `#E5E7EB` |
| 卡片边框 | 1px `#E5E7EB` |
| 强调卡片边框（审批/失败） | **1.5px** 对应语义色描边 |
| 卡片阴影 | `0 1px 2px rgba(16,24,40,.05)` |
| 浮层阴影 | `0 8px 24px rgba(16,24,40,.10)` |

✅ 首选"灰底白卡 + 1px 细边框"建立层级，阴影只是辅助。🚫 禁止重投影、多层阴影。

### 3.4 动效

| 类型 | 时长 | 曲线 |
|---|---|---|
| 微交互（hover、展开） | 120ms | `cubic-bezier(.4,0,.2,1)` |
| 常规过渡 | 200ms | 同上 |
| 脉冲（运行状态） | 1.2s 循环 | 透明度 1 → 0.35 |
| 流式光标闪烁 | 1s 循环 | `steps(1)` |

- 🚫 **单条过渡禁止超过 300ms**。高频操作一天点几百次，每次多 0.2 秒就是几分钟损失
- 🚫 禁止大面积转场、夸张粒子动画、光标跟随动效
- ✅ 动效只服务于"状态变化"，不服务于装饰
- ✅ 必须尊重系统"减弱动效"偏好：关闭动画但**保留颜色区分**

## 4. 页面布局

### 4.1 主框架

```
┌──────────────┬────────────────────────┬──────────────┐
│  侧栏 240px   │   对话执行流 720px 居中   │  工作区 320px  │
│              │  ┌──────────────────┐  │              │
│  会话列表     │  │ 运行状态条 40px   │  │  引用文档      │
│  状态分组     │  ├──────────────────┤  │  产物         │
│  导航入口     │  │ 消息流（滚动）    │  │  结果摘要      │
│              │  ├──────────────────┤  │              │
│              │  │ 输入区（自适应）   │  │              │
└──────────────┴────────────────────────┴──────────────┘
```

| 区域 | 尺寸 | 说明 |
|---|---|---|
| 左侧导航 | 宽 240px（可折叠至 56px 图标栏） | 会话列表 + 状态分组 + 导航入口 |
| 对话执行流 | **内容宽 720px 居中** | 最佳阅读宽度 640–760px。超宽后每行字符数过多，扫读成本陡增 |
| 右侧工作区 | 宽 320px（可折叠为浮层） | 引用文档 / 产物 / 结果摘要。**产物不进对话流** |
| 运行状态条 | 高 40px，sticky 置顶 | 计时、token、模型名、中断按钮 |
| 输入区 | 高度自适应，最小 2 行，最大 8 行 | 工具条 + 输入框 + 发送 |

### 4.2 响应式断点

| 屏宽 | 表现 |
|---|---|
| ≥ 1440px | 三栏全展开 |
| 1024–1440px | 工作区默认折叠为浮层，**点击后滑出，不挤压主布局** |
| < 1024px | 侧栏转抽屉，工作区转全屏浮层，对话流全宽 |

### 4.3 布局规则

- ✅ 侧栏可折叠，但**当前选中项必须有明确标识**（浅蓝底 + 左侧 3px 主色竖条）
- ✅ 内容区左右留 16–24px 边距即可，不学 C 端大边距
- ✅ 表格行高 40–48px，表头固定
- 🚫 禁止弹窗套弹窗（最多 2 层）

## 5. 组件视觉规范

> 以下均为**视觉规格**（尺寸、颜色、间距、状态样式），不涉及实现。

---

### 5.1 会话列表项

| 项 | 规格 |
|---|---|
| 行高 | 36px（内边距 8px 12px） |
| 字号 | 12.5px，标题最多一行，超出省略 |
| 状态圆点 | 7×7px 正圆，位于文字左侧，间距 8px |
| 运行中圆点 | 青色 `#0891B2` + 1.2s 脉冲动画 |
| 选中态 | 底色 `#EFF6FF`，文字转 `#2563EB`，字重 600 |
| hover | 底色 `#EEF0F4` |
| 右端元信息 | 等宽字体 11px `n6`；运行中显示实时计时，其余显示相对时间 |
| 分组标题 | 11px `n6` 字重 600，字间距 0.04em，上间距 12px |

**分组顺序（固定，空组隐藏）**：运行中 → 等待确认 → 已完成 → 失败 → 已中断 → 排队中

**规则**
- ✅ **运行中永远置顶**，不受时间排序影响
- ✅ 会话超过 10 条必须有搜索框
- ✅ 支持 `#tag` 彩色标记，一键筛选

---

### 5.2 运行状态条

位于对话区顶部，sticky 固定，高 40px，底色 `n1`，下边框 1px `n4`。

**内部元素从左到右**：状态圆点 7px → 状态文字 12.5px → 计时（等宽 11.5px）→ token 用量 → 模型名 → 右侧操作区

| 元素 | 样式 |
|---|---|
| 状态圆点 | 7px 正圆，颜色随状态；运行中带 1.2s 脉冲 |
| 计时 | 等宽字体；> 60s 转 `mm:ss`，> 1h 转 `h:mm:ss` |
| token | 等宽字体，格式 `8.6k / 128k`；超过 80% 时数字转橙色 |
| 模型名 | 等宽 11.5px，`n6` 弱化 |
| 暂停按钮 | 描边次级按钮 |
| 中断按钮 | **红色描边/文字按钮**，常驻可见 |

🚫 中断按钮不做实心红块。✅ **中断按钮永不隐藏**——哪怕从不被点击，它的存在本身就是信任来源。

---

### 5.3 消息（用户 / Agent）

| 角色 | 视觉 |
|---|---|
| 用户 | 浅灰气泡 `#EEF0F4`，圆角 12px，最大宽度 80%，**右对齐**，内边距 10px 14px |
| Agent | **无背景无气泡**，直接铺在页面；左侧 28×28px 紫色头像；上方身份行 |
| 系统提示 | 12px 居中灰色细条，无气泡 |

**Agent 身份行**（12px `n6`）：角色名（`n9` 字重 600）+ 紫色 `Agent` 小标签 + 时间戳 + 用时

**Agent 头像**：28×28px，圆角 8px，底色 `#7C3AED`，白色字母/图标

**流式光标**：正文末尾 2px 宽竖线，高 1em，1s steps 闪烁

**规则**
- ✅ AI 消息**不用气泡**——两条消息都用气泡会导致页面变"花"
- 🚫 禁止用户消息与 AI 消息视觉差异过小，长对话下会分不清谁说的

---

### 5.4 执行计划卡 ★ 最高优先级组件

| 项 | 规格 |
|---|---|
| 容器 | 白底，1px `n4` 边框，圆角 12px，阴影 `sh-1` |
| 头部 | 高 40px，底色 `n1`，下边框 1px `n3`；含标题 13px 字重 600、右侧预估文字 11.5px `n6`、右上「编辑」「确认执行」文字按钮 |
| 步骤行 | 高 32px（内边距 7px 0），字号 13px |
| 标记圆点 | 16×16px 正圆，位于文字左侧，间距 10px |
| 完成态 | 绿底 `#16A34A` + 白色 ✓；文字转 `n6` + 删除线（删除线颜色用 `n5`，不与文字同色） |
| 进行中 | 青底 `#0891B2` + 外扩 4px 光晕（用 `#ECFEFF`）；文字 `n10` 字重 600 |
| 未开始 | 1.5px `n5` 描边空心；文字 `n6` |
| 右端元信息 | 等宽 11.5px；完成显示耗时，进行中显示"进行中"，未开始显示"待执行" |
| 编辑态 | 每行右侧出现灰色删除文字按钮；底部出现「+ 添加步骤」，虚线分隔 |

**规则**
- ✅ **计划必须是可勾选、可编辑、可增删的结构化列表**——禁止渲染成纯文本 Markdown 列表（只能看不能改等于放弃纠错窗口）
- ✅ 步骤数量 3–7 步；超过 7 步需折叠子步骤
- ✅ 计划变更时，卡片顶部出现橙色提示条「计划已更新，原第 3 步已移除」

### 5.5 工具调用卡

| 项 | 规格 |
|---|---|
| 折叠态高度 | 38px |
| 容器 | 圆角 8px，1px 边框，内边距 9px 12px |
| 状态图标 | 16×16px 正圆：✓绿 / 脉冲青 / !红 / 空心灰（等待授权） |
| 工具名 | **等宽字体** 12.5px 字重 600，`n10` |
| 写工具标记 | 名称右侧橙色「写」小标签，1px `#FED7AA` 边框，圆角 3px |
| 结果摘要 | 12.5px `n7`，单行省略 |
| 耗时 | 右对齐等宽 11.5px `n6`；> 10s 转橙，> 30s 转红 |
| 卡片底色 | 成功 `#F0FDF4` / 错误 `#FEF2F2` / 运行中 `#ECFEFF` / 等待 中性 `n1` |

**规则**
- ✅ 默认折叠；**出错时自动展开**
- ✅ 结果摘要**必须是人话**：「返回 128 条记录」，禁止 dump 原始 JSON
- ✅ **读工具与写工具必须视觉区分**（写工具加橙色「写」标记）

### 5.7 审批卡 ★ 安全核心

| 项 | 规格 |
|---|---|
| 容器 | 圆角 12px，**1.5px `#FED7AA` 描边** |
| 头部 | 高 40px，底色 `#FFF7ED`，下边框 1px `#FED7AA`；文字 13px 字重 650，色 `#9A3412` |
| 正文区 | 白底，内边距 12px 14px，13px |
| 影响范围块 | 底色 `n2`，圆角 8px，内边距 9px 12px，12.5px `n7`；三行：**影响范围 / 不可逆点 / 依据** |
| 底部操作区 | 内边距 10px 14px，上边框 1px `n3` |
| 按钮 | 批准执行（**绿实心**）· 修改参数（描边）· 拒绝（红色文字/描边，**右对齐**） |

**规则**
- ✅ 标题写**具体动作**：「即将向 12 位客户发送挽回邮件」，🚫 禁止写"确定吗？"
- ✅ 支持局部批准：条目带复选框，可只勾选部分
- 🚫 一个区域内只允许一个实心主按钮

### 5.8 失败卡

| 项 | 规格 |
|---|---|
| 容器 | 圆角 12px，**1.5px `#FECACA` 描边**，白底 |
| 头部 | 底色 `#FEF2F2`，文字 13px 字重 650，色 `#991B1B` |
| 正文 | 三段式，每段标签 11.5px `n6` 字重 600，内容 13px |
| 底部 | 重试这一步（**主色实心**）· 改参数重试（描边）· 终止（文字按钮，右对齐） |

**三段式内容强制**：失败位置 / 原因 / 已完成的部分。🚫 禁止报"出了点问题"。

### 5.9 引用角标

| 项 | 规格 |
|---|---|
| 尺寸 | 15×15px，圆角 3px |
| 默认 | 底 `#E5E7EB`，字 10px 等宽 `n7` |
| hover | 底转 `#2563EB`，字转白色 |
| 位置 | 上标 `vertical-align: super`，左侧间距 2px |

点击后展开来源列表：每条 32px 行高，左侧紫色文档图标 16×16px（底 `#F5F3FF`，边框 `#DDD6FE`），右侧页码/大小等宽 11px `n6`。

### 5.16 登录入口

- 与工作区共用系统字体、灰色页面底、白色卡片、细边框和轻阴影；品牌标识沿用侧栏的 AW 标识，不使用装饰眉题。
- 卡片居中，宽度最多 400px；桌面内边距 32px，移动端 24px，页面两侧至少留 16px。标题使用 H1 阶梯，说明使用次要正文色，登录为唯一全宽主操作。

## 6. 状态视觉语义

全站只允许这 6 种运行状态，**禁止自创**。

| 状态 | 色 | 图标 | 界面表现 |
|---|---|---|---|
| 排队中 | `n6` 灰 | 空心圆 | 显示队列位置 |
| 执行中 | `#0891B2` 青 | 脉冲圆点 | 1.2s 呼吸动画 + 实时步骤流 |
| 等待确认 | `#EA580C` 橙 | ⚠ | **必须置顶提示**：会话列表圆点 + 顶栏角标 |
| 已完成 | `#16A34A` 绿 | ✓ | 显示总耗时与 token |
| 已失败 | `#DC2626` 红 | ✕ | 展开失败卡，给三个恢复选项 |
| 已中断 | `n6` 灰 | ■ | 用户主动停止；保留已完成部分，可续跑 |

🚫 **「已中断」与「已失败」必须区分**：前者不需要道歉文案，后者需要解释原因并给恢复路径。混为一谈会让用户以为系统不稳定。

---

## 7. 三种必做状态

任何承载数据的区域都必须设计这三态，缺一不可。

| 态 | 视觉要求 |
|---|---|
| 加载态 | **骨架屏优于转圈**；骨架形状需匹配即将到来的内容（不能是泛泛的灰条） |
| 空态 | 图标/插画 + 一句说明文案 + **一个引导操作按钮**。禁止只放一句"暂无数据" |
| 错误态 | 三段式：发生了什么 / 为什么 / 下一步能做什么 |

## 9. 无障碍与键盘

| 项 | 要求 |
|---|---|
| 对比度 | 正文 ≥ 4.5:1，大字 ≥ 3:1 |
| 焦点 | 禁止移除焦点轮廓而不给替代样式 |
| 动效 | 尊重系统"减弱动效"偏好，关闭动画但保留颜色区分 |
| 语义 | 审批卡用 `alertdialog` 角色，状态条用 `status` 角色 |
| 播报 | 流式输出对屏幕阅读器是灾难，需提供"生成完成后再播报"开关 |

| 快捷键 | 行为 |
|---|---|
| `Enter` | 发送 |
| `Shift` + `Enter` | 换行 |
| `Esc` | 中断生成 / 关闭浮层 |
| `⌘/Ctrl` + `K` | 命令面板 |
| `⌘/Ctrl` + `/` | 折叠/展开全部工具调用卡 |
| `Tab` | 焦点顺序须符合视觉流，审批卡优先于正文 |

## 10. 验收清单

### P0 · 不做就是黑盒产品

- [ ] 工具调用渲染为卡片，含状态、耗时、折叠入参
- [ ] 执行前展示**可编辑**的计划卡
- [ ] 生成过程中「停止」按钮常驻可见
- [ ] 失败展示三段式：失败位置 / 原因 / 三个恢复选项
- [ ] 不可逆操作有审批卡，写清影响范围
- [ ] 读工具与写工具视觉可区分

### P1 · 决定好不好用

- [ ] 会话列表按状态分组，运行中置顶
- [ ] 会话 > 10 条有搜索
- [ ] 右侧工作区承载产物，不混进对话流
- [ ] 正文阅读宽度 640–760px
- [ ] AI 关键结论带可点击引用角标
- [ ] 运行计时、token、模型名提到顶部常驻
- [ ] 代码块语法高亮 + 一键复制
- [ ] 用户消息与 AI 消息视觉可区分
- [ ] 所有数据区域都有加载 / 空 / 错误三态

### P2 · 拉开差距

- [ ] 自主度三档控件
- [ ] 步骤级干预（"前三步继续，第四步给我看"）
- [ ] token 成本统计看板
- [ ] 命令面板 `⌘K`
- [ ] 场景 chips 暴露 Agent 能力
- [ ] 深色主题可切换

### 视觉自检（每次交付前）

```
1. 全局搜索 #xxxxxx，确认无硬编码色值（代码块高亮主题除外）
2. 眯眼截图检查：主色面积是否 ≤ 5%
3. 检查圆角是否全部 ≤ 16px
4. 检查动效是否全部 ≤ 300ms
5. 检查所有文字对比度是否 ≥ 4.5:1
6. 检查每个数据区域是否都有空态
```

## 11. 避坑清单

❌ 大圆角（> 16px）、重阴影、渐变背景 —— 立刻显得像 C 端产品，不专业
❌ 每个功能卡片配彩色渐变图标 —— 视觉噪音，扫读时全是干扰
❌ 首页堆满"数据大屏"式图表 —— 一线员工需要的是待办和入口，不是看板
❌ 图标不配文字 —— 用户会猜
❌ 动效超过 300ms —— 一天点几百次，累积成本很高
❌ 纯黑背景配纯白文字 —— 光晕毁掉可读性
❌ 什么操作都弹确认 —— 用户会被训练成无脑点通过
❌ 只给一个「重试」按钮 —— 用户需要区分"原样重试"和"改点东西再试"

## 12. 落地顺序

```
第一批（产品成立的前提，一次性做完）
  工具调用卡 → 计划卡 → 状态条 → 失败卡

第二批
  会话列表状态分组 + 搜索 → 工作区面板 → 引用角标 → 输入区工具条

第三批
  审批卡 → 深色主题 → 命令面板 → 成本看板
```

> ⚠️ **不要先做视觉改版再做结构。** 结构不对，换什么风格都不解决问题。
> 如果本次只做一件事，先解决**透明度**——行业里最常见的失败不是模型不够强，而是用户看着转圈以为卡死，直接关掉。
