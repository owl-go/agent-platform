Agent Workspace 录课演示提示词

全部名称、项目、事项和数字均为虚构教学素材，不代表真实客户或线上业务结果。
按“第一轮 → 简短追问 → 选专家 → 保存工作流 → 工作流追问”使用。

一 第一轮会话任务
请将下面的模拟项目进展整理成一份面向项目负责人的周报。
仅使用本次提供的事实。正文包含“本周进展”“风险与阻塞”“下周行动”三个部分，使用 Markdown，总长度不超过 600 字。
区分已完成、进行中和待确认；为行动列出已有的责任人和时间，未提供的信息标注“待确认”。不要为缺失资料补造事实，也不要把测试环境指标描述为线上业绩。

模拟项目：星舟工作室网站升级。
1. 订单模块已完成接口联调，尚未验收。责任人李青。
2. 支付流程在测试环境中的失败率从 1.8% 降到 0.9%，还没有线上数据。责任人王宁。
3. 官网新首页设计已经确认，介绍文案仍等待品牌组反馈。文案反馈时间未提供。
4. 客户培训材料完成初稿，下周二拟安排试讲。试讲责任人未指定。
5. 有两位模拟客户反馈移动端按钮难以点击，尚未复现，也没有修复时间。

二 第一轮追问
把“下周行动”改为一个 Markdown 表格，列包含“行动”“责任人”“时间”“依赖”。未提供的内容写“待确认”。同时保留前两部分，不增加新事实。

三 预建专家的配置
名称：项目周报编辑
介绍：把零散项目进展整理成清晰、可追踪的周报，帮助负责人看到事实、风险和下一步行动。
核心能力：区分已完成、进行中、阻塞和待确认事项；保留原始数据的环境与范围；将进展转化为带责任人、时间和依赖的行动清单。
工作流程：先读取本轮资料，再核对事实和缺口，按三段结构编写周报，最后检查是否把未知信息写成事实。发现缺口时明确标注，不自行补齐。
输出标准：中文 Markdown；依次输出“本周进展”“风险与阻塞”“下周行动”；下周行动使用表格；正文不超过 600 字。
注意事项：不得捏造负责人、截止时间、完成状态或收益；测试指标必须标明测试环境；资料不足时说明缺口。
技能和连接器：核心演示均不选择。

四 选择专家后发送
请用当前选中的项目周报编辑专家，基于刚才的模拟资料再整理一份周报，沿用三段结构和行动表格，保持事实范围准确。

五 保存为工作流
名称：项目周报整理
目标：基于每轮明确提供的最新项目进展，整理一份面向项目负责人的中文 Markdown 周报。依次输出“本周进展”“风险与阻塞”“下周行动”，行动使用责任人、时间和依赖表格，正文不超过 600 字。未提供的内容标注“待确认”，不得编造事实。新一轮明确更新的事项以本轮资料为准，旧事项不能被擅自认定为完成。若没有新进展，先说明需要哪些资料，不编造周报。只整理并返回正文，不发送外部消息。
说明：创建并验证会启动第一轮执行；由于这里没有自动数据源，首次验证可能提示需要资料，这是预期行为。随后在运行对话中提交下面的新进展。

六 工作流新一轮输入
下面是本轮最新的模拟进展，请更新周报，特别区分这次更新与上一轮的状态，不沿用已被明确替换的旧数据：
1. 订单模块已通过验收。责任人李青。
2. 支付流程完成上线，但本轮还没有线上失败率统计。不要将上次测试环境的 0.9% 写成线上指标。
3. 品牌组已反馈官网文案，计划周三上线。责任人王宁。
4. 客户培训已指定赵岚负责，下周二试讲计划保持不变。
5. 移动端按钮问题已经复现，修复时间仍待确认。

七 可选的演示飞书消息
只在已经实际验收的演示机器人与允许的发送者范围内使用：
请整理一份简短的项目状态报告，仅基于以下模拟资料：订单验收已完成；官网文案已确认；移动端按钮问题待修复且时间待确认。请列出风险与下步行动，不要发送到其他聊天。
若工作流目标是三段周报，则按已保存的目标格式执行，不要求渠道改变任务规则。

八 录制后检查结果
检查模型是否标注测试环境，是否误造了线上失败率，是否保留移动端问题的待确认状态，是否按新的输入更新订单状态，是否为未知责任人或时间标注缺口。
不准备“标准生成答案”冒充实际输出；只有确实执行过的结果才作为演示录屏。
