企业统一管理的 Agent 工作台｜三组可复制案例资料与任务
全部公司、人物、政策和数字均为虚构。不得当作真实客户案例或实际收益证据。
课件结果为验收目标/示例。录制时展示系统实际生成的结果，不能粘贴预写结果冒充现场回答。

统一演示企业：虚构的星舟工作室。管理员先验证平台执行默认并准备账号、额度；产品部门资源发布者维护部门知识库；员工保留自己的会话与工作流。

案例一｜项目负责人周然：网站升级周报
A. 第一轮，粘贴到新会话
请将以下虚构的项目进展整理为一份不超过 600 字的 Markdown 周报，交给项目负责人判断现状和下一步。
输出：本周进展、风险与待确认项、下周行动表（事项、责任人、时间、依赖）。
规则：只使用提供的信息；区分联调和验收、测试和线上；缺少的信息写“待确认”，不要自行指派责任人或编造日期。
资料：
1. 订单模块接口联调完成，尚未验收，负责人李青。
2. 支付测试失败率从 1.8% 降到 0.9%，负责人王宁；未提供线上数据。
3. 官网首页设计确认，品牌文案等待反馈，反馈时间未知。
4. 培训材料第一稿完成，下周二试讲，负责人未明确。
5. 两位模拟客户反馈移动端按钮问题，尚未复现，修复时间未知。

B. 如结果存在偏差，用实际偏差补充修正
请检查并修正刚才的周报：联调完成不等于验收通过；0.9% 仅是测试环境指标；资料未提供的责任人、完成时间或依赖应写“待确认”。保留正确事实，重新输出完整周报。

由管理员预建平台专家：项目周报编辑
普通员工先确认目录中可见可用。私有专家也能完成文本任务，但不能作为企业平台共享已经验收的证据。
介绍：将项目进展整理为可检查、可重复使用的周报。
核心能力：整理事实、区分状态、识别信息缺口、提炼风险和下一步。
工作流程：阅读本轮材料；核对状态和指标环境；列出风险与缺口；生成周报和行动表；自查是否混用旧信息。
输出标准：Markdown 本周进展、风险与待确认项、下周行动表；表格列事项、责任人、时间、依赖；默认不超过 600 字。
注意事项：不编造事实、责任人或日期；不把联调写成验收；测试数据注明环境；缺失信息写待确认；有新资料时按本轮资料更新状态。

C. 选入专家后发起新一轮
请按“项目周报编辑”的标准重新整理本轮资料。特别检查联调/验收、测试/线上和未知责任人。只使用本会话明确提供的资料。

D. 保存为工作流
名称：网站升级周报
目标：根据每一轮明确提供的新项目进展，整理不超过 600 字的 Markdown 周报，包含本周进展、风险与待确认项、下周行动表（事项、责任人、时间、依赖）。区分联调和验收、测试和线上。未知内容标注待确认。没有本轮资料时先请求资料；不自动获取外部信息，不发送外部消息。
从已完成的回答转换，检查专家与资源是否正确；创建并验证会启动首轮执行。

E. 在工作流运行对话提交第二轮
以下是新一轮进展，请重新生成本轮周报；更新已变更状态，保留仍缺失的信息。
1. 订单模块已经验收，负责人李青。
2. 支付模块已经上线，负责人王宁；尚未提供线上失败率，不得用上轮测试指标代替。
3. 品牌文案已返回，官网计划周三发布，负责人王宁。
4. 培训负责人确认为赵岚，下周二试讲安排不变。
5. 移动端按钮问题已经复现，修复时间仍未知。
验收：订单更新为已验收；支付线上失败率仍待确认；培训负责人为赵岚；移动端问题不得写成已修复。

案例二｜新人销售小许：产品政策问答
资料：case-product-policy.txt，完整虚构。由产品部门资源发布者上传到部门“星舟产品资料”知识库，等待处理完成并真实检索验证。
智能助手名称：星舟产品答疑。由当前产品部门成员在自己的智能助手中选择有权访问的部门知识库；不演示自动共享员工的助手历史。
服务规则：回答星舟协作台的产品、试用、支持与交付问题；优先以已选择知识库资料为依据；区分标准服务与需另行确认的事项；资料没有给出的价格、日期、支持范围不得自行承诺；回答简洁，保留可用来源。
选择该演示知识库。为验证检索，不为以下问题配置同文固定 FAQ。
问题一：团队版是否包含周末支持？定制单点登录几天能交付？
验收目标：工作日 09:00–18:00 标准支持；周末支持需另行确认；单点登录交付天数未约定，需要需求评估；来源对应资料第 2、3 节。
问题二：客户很着急，你能保证定制单点登录明天上线吗？
验收目标：不作保证，明确需要评估和负责人确认；不能编造工期。
展示知识库实际检索片段并对照回答；回答如果带来源说明则按实际展示。助手聊天当前没有独立引用展开控件，不演示不存在的按钮。检索不可用则只展示课件示例，不称为现场成功。

案例三｜运营负责人：会议行动跟进
工作流名称：试讲会议行动整理。
目标：根据本轮明确提供的纪要或补充信息，输出 Markdown 行动表，列事项、责任人、时间、依赖和待确认项。没有明确责任人或期限时写待确认，禁止自行分配。将已明确补充的信息用于新一轮结果；信息冲突时列出冲突请求确认。不写入外部任务工具，不自动发消息。
A. 首轮输入
请整理这段虚构试讲会议纪要，输出行动表：
赵岚负责下周二试讲，需要拿到报名页链接。李青在本周五前修改报名页；培训提醒名单周一前完成，但负责人还没确定。这里没有说明报名页修改依赖哪些资料。
不要把相对日期换成自行猜测的绝对日期。
验收：赵岚/下周二、李青/本周五保留；提醒名单负责人待确认；未提供的依赖待确认。
B. 在原网页运行对话，或已先发送 A 的同一机器人聊天中发起追问
网页与消息渠道不自动共用会话历史。聊天闭环应先发 A，再在同一聊天发 B。
补充刚才的试讲会议：培训提醒名单由林乔负责，周一中午前完成。请按补充信息更新行动表，其他明确事项保留；不创建外部待办。
验收：新结果更新名单负责人和时间；不声称已创建或已通知；若从消息渠道发起，回复返回原聊天。
消息渠道演示前：机器人连接 → 一次性配对识别 → 所有者确认允许发送者并保存 → 验证收发 → 启用。未完成验证就在网页展示，不实际发聊天消息。
