企业统一管理的 Agent 工作台
Agent Workspace 企业价值与案例课｜录课方案

课程目标
用户确认的定位：企业统一管理的 Agent 工作台。
一句话价值：企业统一准备模型、共享方法、业务资料与使用规则，员工在自己的工作空间完成任务、检查结果并复用。
受众：企业管理者、业务负责人及潜在员工用户；了解企业采用价值，并学会从一件任务开始。
成片：12 分 40 秒；现场等待可剪辑，整体控制在 10 至 15 分钟。
企业目标：让 AI 能力有一致的供给方式，让业务资源在权限范围内使用，让员工的重复任务可以持续执行，同时管理账号和使用额度。
员工目标：使用企业已准备的能力，减少重复配置和解释，把任务做出结果并验证后续复用。
课程完成后，观众能说清企业统一管理哪些内容、员工私有边界在哪里、哪些场景适合先试用，以及怎样以具体结果评价效果。

叙事顺序
企业目标与角色 → 企业使用 AI 的痛点 → 统一管理解决的问题 → 企业供给到员工使用的流程 → 场景 → 三个案例 → 企业试用的起步方式。
前 40 秒说清定位；前 5 分钟解释企业价值；后半段展示业务产出。系统菜单只作为案例实现的证据。
所有痛点均为供观众自我判断的工作场景，不冒充市场调查结论。案例公司、人物、政策和数值均虚构，不使用客户见证或量化收益承诺。

案例一：项目周报，从进展汇总到风险判断
企业前提：星舟工作室管理员已验证平台默认执行配置，准备平台“项目周报编辑”专家；员工默认继承执行配置。
人物：项目负责人周然，在自己的会话与工作流中使用企业准备的标准，说明网站升级现状与下一步。
原来流程：复制多人更新 → 逐条判断是否完成 → 重写周报要求 → 手工改成行动表 → 下周重新开始。
系统流程：选用可见的平台专家 → 给出本轮进展 → 按固定周报标准整理 → 核对事实与缺口 → 保存为工作流 → 用下一轮进展再次执行。
具体产出：一份 Markdown 周报、风险清单、责任人/时间/依赖的行动表。
价值落点：把联调与验收、测试与线上、已确认与待确认区分开；后续复用同一标准。不要只强调“文案更好看”。
现场重点：第一轮不能把 0.9% 测试失败率写成线上指标；第二轮订单已验收，但线上失败率仍缺失。

案例二：产品问答，从反复找人到按资料回答
企业前提：产品部门的资源发布者建立演示部门知识库并完成处理；小许是当前部门成员。
人物：新销售小许，被客户问到试用、标准支持与定制交付。
原来流程：搜索旧聊天 → 找产品同事 → 拼凑答复 → 无法确认引用哪一版资料。
系统流程：产品政策进入部门知识库并处理就绪 → 成员自己的智能助手选择可访问资料并限定服务范围 → 提问并检索 → 按资料回答 → 检查来源与未约定事项。
具体输入：“团队版是否包含周末支持？定制单点登录几天能交付？”
具体产出（按资料检查助手实际回答）：标准支持为工作日 09:00–18:00；周末支持需另行确认；定制单点登录交付时间未约定，需需求评估。来源是演示资料的第 2、3 节。
价值落点：常见问题可以有一致依据，新需求保持明确边界；不承诺答对所有问题，也不把知识库称为模型训练。

案例三：会议行动，从一段纪要到下一步
企业前提：已验证的默认能力与适当使用额度；运营人员的工作流和消息渠道由自己维护。
人物：运营负责人，需要把试讲会议意见整理成后续执行清单。
原来流程：重新读纪要 → 猜谁来做和何时完成 → 复制到表格 → 在群里继续问。
系统流程：提供纪要 → 工作流按行动表标准提取 → 明确缺口 → 在已验证、允许的机器人聊天里补充信息 → 新一轮结果返回原聊天。
具体产出：试讲、报名页、提醒名单三项行动；提醒名单负责人留为待确认。补充“由林乔负责，周一中午前完成”后更新该项。
价值落点：把讨论落实为可核对的下一步，并让发起与回复留在常用聊天入口。生成行动表不等于已经向外部任务系统创建待办。

录制前准备
1. 演示环境准备管理员、产品部门资源发布者和普通员工账号；管理员验证平台默认执行配置，员工继承默认配置，并有足够可用 Credits；三个任务至少预跑一次。
2. 由管理员预建平台“项目周报编辑”专家，普通员工确认可见可用；主案例展示关键标准，不逐字段录入。若只准备了员工私有专家，必须说明它尚未是平台共享资源。
3. 产品部门资源发布者准备部门知识库“星舟产品资料”和 case-product-policy.txt，确认 Ready、真实检索可用；同部门员工的“星舟产品答疑”智能助手先完成验证。不用管理员权限代替部门成员访问验证。
4. 会议行动工作流提前跑通；需要演示聊天时，提前完成机器人账号连接、发送者配对确认、保存、收发验证与启用，并在同一机器人聊天先发送案例三 A，再发送 B，不能沿用网页运行的历史。不要录制密钥。
5. 外部连接器不是三个文本案例的必要条件。如额外演示外部资料读取，只选已经安装、授权且通过当前账号真实读取验证的工具。
6. 网络/模型等待超过约 15 秒时剪辑；使用历史录屏须标注“同一案例预录”。现场结果与预期不同就检查或修正，不照稿说成功。
7. 1920×1080 或 1280×720 录制；关闭通知，用虚构资料；准备 20 秒音量测试。

案例二：拍一个问题、知识库实际检索片段和助手回答；配置项只在需要说明标准时短暂出现。

片尾：回到“选一件重复工作”的行动建议。

临场替代
知识库未就绪或检索失败：只讲资料到问答的流程，展示标明“预期回答示例”的课件，不声称现场已检索成功。
消息渠道未验证：只展示网页工作流的输入与产出；聊天闭环用流程图讲解，不以静态图冒充真实收发。
工作流创建：说明“创建并验证”会启动第一轮；没有新资料时先请求输入，提供本轮资料后再执行。不宣称只保存、不启动。
结果有误：展示具体偏差，补充要求后再核对。一次正确或错误的结果都不能证明整体准确率。

讲者事实边界
专家固定工作方法和输出标准，不决定模型；专家团队当前按顺序执行。
连接器供任务经授权访问外部工具；消息渠道供允许的聊天触发工作流并收回复。
上传保存资料不等于已可检索；知识库需要处理完成且检索服务可用。
定时、API 与消息触发是执行入口，不能代替新资料来源；未配置资料读取就需要提供新材料。
公开进度/允许的摘要和最终结果有区别，不介绍为完整内部思维链。
本课不展示外部系统写入、自动派发任务、自动公布私人内容或保证准确的无人值守决策。
企业统一管理是本课产品定位，不改变领域中的个人私有资源语义；不声称管理员能读员工会话、工作流、文件或单次执行消费明细。
模型目录由管理员维护，员工默认继承平台执行配置，也可以在目录中维护个人选择；不讲成管理员强制同一模型。
部门共享重点演示知识库；专家、技能按现有平台资源权限演示，不编造部门专家或部门工作流共享。
使用额度与部门预算是 Credits 管理，治理记录只涵盖允许的管理操作；不讲成供应商账单、完整成本归因或员工行为监控。

企业试用练习
管理员：验证一个平台执行默认，准备演示用户与适当额度。
业务负责人/资源发布者：准备一份可共享、可核实且权限明确的资料；把一套方法整理为可用资源。
员工：选一件重复工作，写清输入、结果和三条标准，完成第一轮，再用新资料执行第二轮。
验收：默认可用、资源范围正确、产出符合标准、账号与额度管理按配置生效。只在实际执行后记录观察，不推断全企业收益。
