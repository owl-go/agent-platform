企业用 Agent，最怕各用各的。
每个人自己配环境、自己摸流程，好方法也留在个人手里。
所以我做了 Agent Workspace：企业统一配置 Agent 运行环境，大家用统一的流程和方式做事。
技能可以沉淀，专家和连接器可以复用，还能打通钉钉、飞书这些消息渠道。
接下来，直接看企业怎么配置，员工怎么使用。

此工具已经开源，有想要源码或者自己想要部署体验的朋友，可以在评论区回复 666。

先看企业统一的运行环境。
管理员集中维护模型连接、可用模型和运行引擎，再设置企业默认。
员工进入平台，就可以继承这套配置，不用每个人从安装工具、填写地址开始。
如果有不同的任务要求，也可以显式选择自己的执行配置。
这里统一的是企业提供的运行基础，模型和引擎的实际可用性，仍然以部署和验证结果为准。

有了环境，还需要统一做事的方式。
比如同样是做一份商品研究，我们希望大家都先补齐输入，再收集证据，按相同的判断规则分析，最后按约定的格式交付。
这些要求可以写进专家指导和技能。
会话适合处理当前问题，Workflow 则把固定目标和可重复执行的配置保存下来。
员工面对的是同一套入口和操作逻辑，任务要求、授权确认、执行活动和结果都能在平台里找到。

接着看技能沉淀。
一个技能，除了告诉 Agent 能做什么，还要写清需要什么资料、按什么步骤做、哪些情况要追问、什么条件下必须停止。
比如商品研究，成本条件不完整时，先补资料，再调查需求和竞争，不能直接给出看似完整的结论。
这些方法整理成 Skill 后，可以通过 Git 或 ZIP 安装。
后续执行引用冻结的修订，方法更新后，也不会悄悄改写过去的执行记录。

专家解决的是岗位经验怎么被团队使用。
在专家目录中，可以选择对应的专业指导、工作流程和输出标准，并绑定需要的技能与连接器。
这些配置让经验进入实际任务，而不是停留在一段个人提示词里。
需要多人分工时，可以使用专家团队，由领队协调成员，再汇总形成正式结果。
平台和部门资源按权限共享，员工自己的会话和私有内容，仍然保持隔离。

连接器让 Agent 接入企业正在使用的系统。
文档、协作工具、业务数据，都可以通过对应的连接器提供工具能力。
企业维护可用的接入定义，员工再完成自己的账号授权。
这里复用的是连接方式和工具能力，不是把一个人的账号权限交给所有人。
访问范围仍然跟着当前使用者走，需要确认的高风险操作，也不能因为已经连接就自动放行。

消息渠道，则把 Agent 带到员工日常聊天的地方。
比如从钉钉、飞书或企业微信发起问题，由绑定的 Workflow 执行，再把答案回复到原聊天。
连接器解决 Agent 怎样调用工具，消息渠道解决人从哪里提问、在哪里收到结果。
接入时要确认账号、允许的发送者和聊天范围，再完成真实收发验证。
这次本地环境只说明接入方式，不把尚未验证的渠道演示成已经跑通。

再看员工实际使用的入口。
新建会话，选择合适的专家和资源，说明目标与交付要求，就能在同一个界面推进任务。
执行时可以查看活动，遇到授权或确认要求，再由使用者完成相应操作。
如果同类任务会反复出现，就整理成 Workflow，保存固定目标和执行配置。
这样，企业建设的环境、专家、技能和工具，最终都回到员工每天做事的过程中。

企业统一管理，也需要保留清楚的边界。
账号、共享资源和适用的用量预算可以集中治理。
个人内容、外部账号授权和操作确认，仍然按照各自的权限处理。
统一平台，并不意味着管理员可以随意查看每个人的私人会话。
企业有共同的基础，员工也有明确的使用边界。

这就是 Agent Workspace 想解决的问题。
让企业统一建设 Agent 的运行环境和工作方式，把业务方法逐步沉淀下来，再连接实际系统与消息入口。
单个人用上 Agent 只是起点，让整个企业用同一套基础持续开展工作，才是这套产品的重点。
