# Domain Docs

This repository uses a single-context documentation layout for engineering-skill discovery.

## Required reading

- Read the root `CONTEXT.md` before naming or changing domain concepts.
- Read the relevant ADRs under `docs/adr/` before changing an established architectural decision.
- Follow the product and technical document routing in `AGENTS.md`; a target capability in a specification is not evidence that the capability is implemented.

## Vocabulary

Use glossary terms exactly as defined in `CONTEXT.md`. Do not introduce synonyms for Session, Workflow, Run, Workspace, Artifact, Expert, Extension, Model Provider Connection, Provider Model, Model API Protocol, Response Snapshot, Runtime Engine, User, or Administrator.

## Decisions

If a proposed change contradicts an accepted ADR, call out the conflict explicitly and create a superseding ADR rather than silently diverging.
