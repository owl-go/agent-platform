## Package validation

The package validator is the single boundary shared by ZIP upload and guided creation. It rejects empty or oversized archives, absolute or traversal paths, duplicate paths, symbolic links, hard-coded credential names or values, malformed JSON, missing required files, invalid semantic versions, and packages that declare both MCP and CLI manifests. A package must contain at least one `skills/<name>/SKILL.md`; every document must be UTF-8 with valid frontmatter and all referenced resources must stay inside that Skill directory.

The outer Connector Package ZIP still rejects symbolic links. Its nested immutable CLI bundle may contain only relative symlinks that resolve within the bundle, matching the CLI bundle extractor; absolute and escaping links fail validation. This permits the verified npm `.bin` links used by `@larksuite/cli` without weakening the outer package or Runtime mount boundary.

Catalog Revision and Installation responses expose `examples_zh` and `examples_en` from their exact metadata. Installation details also expose their mode and display icon so private packages can launch the correct Conversation Selection kind. Examples are display data and only enter an unsent Conversation Draft after the User chooses one.

`connector-meta.json` owns the globally unique lower-case `source`, semantic `version`, package `type`, user-facing name and description, examples, platform compatibility, and `auth_mode`. `mcp.json` declares one remote HTTPS or local fixed-runtime server. `cli.json` declares the managed runtime, executable, structured lifecycle argv arrays, status matching, authorization-domain allowlist, reviewed capabilities, and optional resource limits. A CLI package may carry `cli-bundle.tgz`; its executable path, expanded tar contents, mode bits, and SHA-256 are verified before object storage. No manifest accepts a shell command string. CLI source metadata may carry reviewed `agentWorkspace.resourceLimits` (`cpuMillis`, `memoryMiB`, `childProcesses`); the Builder and managed Runtime reverification preserve these limits. Startup Conformance and actual command execution share the same default resource caps and apply lower declared limits rather than testing with a more generous fixed process budget. Bundle/Runtime evidence proves startup under the tested profile; it does not validate a later, different resource profile merely because the bundle is unchanged.

## Lifecycle

Connector Revision, Installation, and Authorization are separate state machines. The active revision is changed only after validation. An invocation requires an available revision, an installed package, an active authorization when the package requires one, current policy, and passed Conformance evidence for the exact CLI bundle SHA-256 and selected Runtime RepoDigest. The manifest's declared digest is required for staging; a different Runtime is allowed only when that exact bundle also has passed Conformance evidence for its RepoDigest. Managed CLI packages are projected into the same catalog as legacy definitions, but selection freezes the verified bundle, capability policy, runtime digest, and installation authorization. Legacy CLI definitions retain definition-scoped Conformance lookup; managed packages use bundle-scoped lookup because their Installation ID differs from the definition that produced the evidence. Disablement and revocation fail closed before a new external process or request is started. CLI credentials are materialized only for one broker command: provider-owned packages receive `CONNECTOR_CREDENTIALS_JSON`; the reviewed DingTalk CLI receives only a short-lived token in `AGENT_PLATFORM_DWS_ACCESS_TOKEN`, while its rotating refresh token remains in platform-encrypted storage. Broker output is redacted before it crosses the Runtime boundary. MCP HTTP targets are checked against the declared Egress host list during materialization and isolated tests.

完整平台发布在服务切换前，对当前启用的托管 CLI Installation 按不同 bundle SHA-256 去重，读取 Object Store 中的不可变 bundle 并复核 SHA-256，然后在候选 Runtime RepoDigest 下运行隔离 CLI Conformance。仅通过的组合写入证据；缺失 bundle、找不到原始 Definition、Conformance 失败或写入失败都会停止发布，线上配置维持原值。该验证只证明 CLI 在受限容器内可启动，不证明特定租户的外部 API 或授权已可用。

For a selected managed CLI Connector, the execution snapshot also freezes the package object key and SHA-256. The Worker verifies that exact package, mounts its bundled `skills/*/SKILL.md` files read-only, and points the Runtime at a Connector-specific Skill before any CLI call. The official Feishu package includes a router Skill and all 28 upstream Skill entry points from the pinned CLI version, with their references; the older built-in Feishu CLI Definition mounts the same resources. The root router and common reviewed flows are loaded into the initial Runtime instruction. Selection supplies usage instructions; it never bypasses the broker's capability, authorization, scope, or approval policy. A browser-restored unsent draft whose selected managed CLI revision predates the current Installation is resolved into a new Conversation Selection before submission, preserving the draft text and Connector identity without mutating either frozen revision.

P1 adds a platform Publication projection above immutable revisions. A Publication selects one active revision for a package source and records its available or disabled state, the Administrator that changed it, an optimistic version, and update time. Publications never own User credentials. A User Installation selects one published revision and one current Authorization while retaining other account Authorizations for explicit selection. Creating or selecting another Authorization does not revoke the remaining accounts; disconnect and revocation operate on the targeted Authorization and clear the selected reference only when it points to that record.

CLI package manifests may select only a built-in authentication driver: `none`, `connector_package`, `feishu`, or `dingtalk`. Packages without the field retain the P0 derivation from `auth_mode`. Provider drivers are platform code and cannot be supplied by a package.

MCP environment values of the form `${NAME}` resolve only against that Connector Authorization's decrypted JSON variables, never the host environment or another Connector. Missing or empty references fail before process startup. This permits stdio packages such as AI-Hive to receive `${MCP_BEARER_TOKEN}` through their upstream `AI_HIVE_MCP_KEY` environment variable without putting credentials in argv. Native Runtime configuration and the isolated MCP probe share this projection; all grant values remain subject to exact-byte redaction.

The execution plane returns `{ok,data,request_id,warnings}` on success and `{ok:false,error:{type,message,retryable,next_action},request_id}` on failure. A missing or whitespace-only target returns `invalid_request` with corrected command guidance before credential resolution or Approval creation; it must not be reported as an unavailable confirmation service. Low-risk calls may omit the target. Supplying it never bypasses User confirmation.
