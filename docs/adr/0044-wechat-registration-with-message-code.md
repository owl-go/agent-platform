# 微信通过公众号文本消息确认浏览器登录码

2026-10-06，用户确认将微信登录改为“关注公众号后发送一次性登录码”。真实个人公众号的 stable token 和服务器握手已通过，但带参数二维码接口返回 48001；因此使用普通关注二维码，并以安全模式加密文本消息中的登录码确认 Registration Attempt。这取代 ADR-0043 中微信 subscribe/SCAN 和二维码 ticket 的确认方式，Keycloak 凭证权威、账号命名空间及飞书企业校验保持不变。

登录码与 OIDC 兑换 code 分开，具有 60 位随机熵和五分钟有效期；只向绑定浏览器显示，数据库仅索引其 hash，显示值和外部身份仍存于加密 payload。发送者来自验签解密后匹配 App ID、公众号原始 ID 和时间的消息，首次确认按 CAS 锁定一个身份；重复回调幂等，其他发送者不能覆盖身份。关注/扫码仅引导进入对话，不确认 Attempt，也不宣称仅凭浏览器可证明关注状态。网页仍需绑定 Cookie、同源完成请求和原 PKCE 才能完成登录。

使用加密被动回复说明操作及确认结果，不调用高级二维码、用户资料或客服发送接口。部署前的旧 ticket Attempt 不包含登录码，应显示过期恢复操作；不把它们转换成新挑战。真实手机发送登录码和首次/返回账号登录仍需单独验收。
