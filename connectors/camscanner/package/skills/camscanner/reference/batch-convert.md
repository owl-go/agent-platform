# 批量文档转换工作流

> **前置阅读**：`references/image-processing.md`（图片命令参数）、`references/pdf-processing.md`（PDF 命令参数）

## 场景

用户有多个文件需要统一转换格式，如一批扫描件转为可编辑文档。

## 决策流程

### 1. 确认输入文件

- 复用已有附件和路径，核对文件列表；保留用户指定顺序，否则自然排序，仅在会影响结果的歧义无法解决时追问
- 确认文件格式和目标格式
- **硬限制：多图合并（merge-*）单次最多 100 张输入图片**

### 2. 超过 100 张时的处理

当输入文件数超过 100 张：
- **不要自动分批**——CLI 没有 PDF/Word/Excel 合并命令，分批产出无法再合成单个文件
- Agent **必须**告知用户：「当前最多支持 100 张图片合并为一个文档，超过 100 张无法合成单文件」
- 如果用户接受多个分卷，可按每批 ≤100 张分别执行，明确标注卷号
- 如果用户必须得到单个文件，告知当前不支持

### 3. 选择转换策略

| 输入 | 目标 | 策略 | 命令 |
|------|------|------|------|
| 多张图片（≤100）→ 1 个文档 | Word/PDF/Excel | 合并 | `image merge-word/pdf/excel` |
| 多个 PDF → 1 个文件 | 任意 | 当前不支持，告知用户 | 无 PDF 合并命令 |
| 1 个 PDF → 可编辑格式 | Word/Excel/MD | 转换 | `pdf convert --format xx` |
| 1 个 Office 文档 → PDF 或格式升级 | PDF/DOCX/XLSX/PPTX | 转换 | `office convert` |
| 多个独立文件 → 各自转换 | 各异 | 逐个执行 | 依次调用对应命令 |

### 4. 执行与确认

- 按 `SKILL.md` 保存策略处理最终产物；未指定保存方式时使用 `-o path -s`（PDF 转图片用 `-d dir -s`），云保存时配合 `--save-title`。
- 核对产物数量、页数和顺序；按实际成功阶段反馈本地文件与云端返回的真实链接，缺失链接时说明结果不完整。
- 独立文件失败时记录结果，只有未触发主文档的尝试上限或同类累计失败停止条件时才继续处理其他文件；汇总成功、失败和未处理项。
