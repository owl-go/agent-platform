# Agent Workspace 前端界面规范

本文件适用于 `frontend` 下的全部界面改动。目标是保持界面克制、一致且可本地化；新增页面应复用现有交互语言，不为视觉装饰添加没有产品含义的信息。

## 实施顺序

1. 先检查相邻页面和已有组件，确认可复用的 Element Plus 组件、布局和交互状态。
2. 以当前产品信息层级组织页面：一个主标题、必要的说明、主体内容和操作。只有帮助用户决策的信息才进入界面。
3. 所有用户可见文本和无障碍标签接入 `frontend/src/i18n`；同时检查中文与英文界面。
4. 完成桌面端和移动端布局，并为本次行为增加相邻测试。
5. 运行相关前端测试、`make web-typecheck` 和 `make web-build`。完成说明必须区分“本地构建通过”和“已经发布”。

## 组件与视觉一致性

- 表单、按钮、标签、弹窗、提示、空状态和加载状态优先使用 Element Plus。已有产品组件能表达需求时直接复用。
- 会话界面是所有对话体验的基准。Workflow 的 Run Conversation 与 Session 使用一致的消息角色布局、消息流宽度、输入框、附件入口、发送/停止状态、加载反馈和移动端行为。
- 同类资源的列表、详情、编辑和删除确认保持相同的标题层级、间距和操作位置。差异只来自真实业务能力。
- 弹窗只显示一个本地化标题。表单内容紧随标题，取消和主操作放在统一的底部操作区。

## 信息层级与文案

- 页面使用一个本地化主标题；副标题仅用于解释用户当前需要理解的产品行为。
- 直接显示名称和必要状态。省略全大写英文眉题、英文装饰副标题、截断 ID、资源卡片代号和重复标题。
- 页面、章节和资源卡片不使用 `01`、`02`、`WF-01` 等装饰编号。只有编号会影响业务理解或操作时才显示，例如 Expert Team 的成员执行顺序、分页页码和步骤进度。
- 自动选择不是装饰状态。不要显示 `AUTO` 或 `AUTO RUNTIME`；当用户确实需要辨认该选择时，使用本地化的“个人默认”。
- API、Runtime、MCP、Skill、Git、URL、模型名、协议名、文件格式和环境变量名属于用户需要识别的技术术语，可以保留。
- 中文界面不混入硬编码英文说明。英文界面也必须来自同一个 i18n key，而不是模板中的另一份文案。

## 导航与位置

- 返回按钮位于内容区域左上角，与主标题左边界对齐；在 Grid 或 Flex 中显式设置左对齐，避免按钮被拉伸后内容居中。
- 打开详情或编辑页时，左侧导航继续选中所属一级模块：Workflow 详情选中“工作流”，Expert 和 Expert Team 编辑页选中“专家”。
- 桌面端和移动端保持相同的信息顺序。移动端可以折叠导航或堆叠操作，但不能隐藏核心操作。

## 禁止引入的装饰信息

以下内容没有明确产品语义时不得加入界面：

- `01 / CONVERSATIONS`、`02 / REPEATABLE EXECUTION` 等英文栏目眉题
- `WORKFLOW / <ID>`、`EXPERT PROFILE`、`PERSONAL DEFAULTS` 等重复说明
- `OUTPUT / 90 DAY FILE RETENTION`、`BEHAVIOR / PERSONAL` 等全大写解释条
- `WF-01`、表单章节序号等视觉编号
- `AUTO`、`AUTO RUNTIME` 等无操作价值的默认状态标签

## 验收清单

- 逐页检查 Session、Workflow、Expert、Expert Team、Settings 及其弹窗，确认没有装饰性英文、重复标题或无意义编号。
- 检查详情页返回按钮位置和左侧导航选中状态。
- 检查 Session 与 Run Conversation 的消息流和输入区在桌面端、移动端保持一致。
- 测试应覆盖容易回归的结构，例如装饰文案不存在、父级导航保持选中、返回按钮使用左对齐布局。
- 最终执行相关 Vitest 用例、`make web-typecheck`、`make web-build` 和 `git diff --check`。
